Lesson 5 — HTML Forms & JS Validation

Student builds a sign-up form with styled inputs, real-time validation and inline error messages.

Duration: ~30 minFile: signup.htmlPrerequisite: Lessons 1–4

Learning objectives

  • Build a form using <form>, <input>, <label>, <button>
  • Use at least 4 different input types correctly
  • Read form values with .value in JavaScript
  • Validate fields and show inline error messages
  • Use return to stop a function when validation fails
  • Style inputs with CSS including :focus state

Teaching notes

Slide 3 — Form element and input types

Start by showing a real sign-up form (Gmail, Instagram) and asking her to identify each input type. This makes the abstract concrete before writing any code.
Always use type="button" on your submit button, not type="submit". The default submit behaviour reloads the page — confusing for beginners who haven't learned about form submission yet.

Slide 4 — Reading form values

Explain .value vs .innerHTML: .value reads what the user typed into an input. .innerHTML changes what's displayed in a tag. Students often mix these up.
Demo in console: type into a real form field, then run document.getElementById("fieldId").value — she'll see it update live as she types.

Slide 5 — Error messages on the page

Explain why inline errors are better than alert() — alerts block the page and users can't see the form behind them. Professional apps always use inline messages.
Show her how to add a red border to an invalid input: input.style.borderColor = "red". Then clear it when valid: input.style.borderColor = "".

Slide 7 — Checkbox and radio

Radio buttons MUST have the same name attribute to work as a group — otherwise they don't exclude each other. This is the most common radio button mistake.

Common errors to watch for

ErrorLikely causeHow to fix

Key patterns to reinforce

Validation pattern

function validate() {
  let val = document.getElementById("field").value;
  if (val.trim() === "") {
    showError("field", "Required!");
    return false;
  }
  return true;
}

Show/hide error helper

function showError(id, msg) {
  document.getElementById(id + "Err")
    .innerHTML = msg;
}
function clearError(id) {
  document.getElementById(id + "Err")
    .innerHTML = "";
}

Wrap-up questions

  • "What's the difference between .value and .checked?"
  • "Why do we use return inside a validation function?"
  • "What does .trim() do and why is it useful?"
  • "How would you check if two passwords match?"

Teaching notes

Slide 3 — What is localStorage?

Open DevTools → Application → Local Storage before writing any code. Show her the empty storage, then type localStorage.setItem("test", "hello") in the console and watch it appear. Very satisfying "wow" moment.
Contrast with sessionStorage (clears when tab closes) and cookies (sent to server). localStorage is the simplest — right tool for this lesson.

Slide 4 — Storing objects with JSON

This is the hardest concept in the lesson. Take extra time here. The analogy that works: JSON.stringify is like packing your object into a box. JSON.parse is unpacking it. The box (localStorage) only holds text.
Demo what happens without JSON: localStorage.setItem("obj", {name:"Sarah"}) — it saves "[object Object]". Then show JSON.stringify fixes it.

Slide 5 — Persisting the to-do list

The key insight: call saveTasks() immediately after any change (add, delete, toggle). Then on page load, the first line reads back from storage. This is the pattern used in real apps.

Slide 7 — Dark mode

classList.toggle() is a great teaching moment — it's elegant and students love how little code it needs. Compare to the if/else version to show why toggle is better.

Common errors to watch for

Save after every change

  localStorage.setItem("tasks",
    JSON.stringify(tasks));
}

Wrap-up questions

  • "What happens if you call getItem() on a key that doesn't exist?"
  • "Why do we need JSON.stringify() before saving an array?"
  • "What's the difference between localStorage and sessionStorage?"
  • "How would you save the user's preferred font size?"

Lesson 7 — Fetch API & Live Data

Student learns to call real APIs using fetch(), handle JSON responses, and build a joke generator and Pokemon lookup app.

  • Use .catch() to handle network errors
  • Display API data on the page using innerHTML
  • Use template literals to build HTML strings cleanly

Teaching notes

Slide 3 — What is an API?

Open Network tab in DevTools, then go to a weather website. Show her the API calls happening in real time — she's already using APIs every day without knowing it. Very eye-opening moment.
The waiter analogy: you (the app) give your order to the waiter (API). The waiter goes to the kitchen (server) and brings back your food (data). You never go to the kitchen yourself.

Slide 4 — fetch basics

fetch is asynchronous — this is a big concept. The code after fetch() runs immediately, before the data arrives. That's why we put our display code inside .then(). Don't skip this explanation.
Start in the DevTools console: fetch("https://official-joke-api.appspot.com/random_joke").then(r=>r.json()).then(console.log). Watch the joke object appear. No HTML needed yet!

Slide 5 — Joke generator

Show the "Loading..." pattern explicitly. Without it, there's an awkward gap where nothing appears. This is standard UX in every app — always show the user something is happening.

Slide 6 — Template literals

This is a great quality-of-life upgrade. Show the before (string concatenation with +) vs after (template literal with backticks). Students always prefer backticks once they see them. Mention the backtick key location (top-left on most keyboards).

Slide 8 — Pokemon challenge

The PokeAPI is free and doesn't require a key — perfect for beginners. Remind her to .toLowerCase() the input before fetching — "Pikachu" and "pikachu" give different results.

Common errors to watch for

ErrorLikely causeHow to fix
CORS error in consoleAPI doesn't allow browser requestsSwitch to a CORS-friendly API like JSONPlaceholder or PokeAPI
data is undefinedForgot to call .json() or returned wrong thingCheck the .then() chain — must return response.json()
fetch runs but nothing showsCode after .then() runs before data arrivesAll display code must go inside the .then() callback
Pokemon not found errorCapitalised name or trailing spaceUse .toLowerCase().trim() before building the URL
Template literal not workingUsing quotes instead of backticksTemplate literals use backticks ` not single or double quotes

Key patterns to reinforce

Standard fetch pattern

fetch(url)
  .then(r => r.json())
  .then(data => {
    // use data here
  })
  .catch(err => {
    // handle error here
  });

Template literal HTML

list.innerHTML += `
  <div class="card">
    <h3>${item.title}</h3>
    <p>${item.body}</p>
  </div>`;

Wrap-up questions

  • "What does .then() do and why do we need it?"
  • "What's the difference between fetch() and a normal function call?"
  • "Why do we always add .catch()?"
  • "How would you fetch and display the top 10 Pokemon?"

Lesson 8 — Final Project: Portfolio Website

Student builds a complete multi-section portfolio website using all skills from Lessons 1–7.

Duration: ~30 minFiles: index.html, style.css, app.jsPrerequisite: All lessons

Learning objectives

  • Link a separate CSS file with <link> and a separate JS file with <script>
  • Apply Flexbox to the navbar and project card grid
  • Implement dark mode using classList.toggle and localStorage
  • Add smooth scroll to anchor links
  • Include a contact section using form validation from Lesson 5

Teaching notes

Slide 3 — Page structure

Explain the 3-file approach — this is how real projects are structured. index.html is the skeleton, style.css is the skin, app.js is the brain. Keeping them separate makes the code much easier to manage.
Use <section> instead of <div> for major page areas — it's more semantic and means something to browsers and screen readers. Each section gets an id so the navbar links can scroll to it.

Slide 4 — Hero section

Encourage her to personalise every detail — her real name, real interests, her own colour scheme. The more personal it is, the more motivated she'll be. This is HER portfolio.
Smooth scrolling tip: add scroll-behavior: smooth to the body in CSS. Then href="#projects" on a link will scroll smoothly to that section — no JavaScript needed!

Slide 5 — Projects section

Point out that she already has real projects from previous lessons — About Me page, JS Playground, To-Do App, Joke Generator. These go in the projects section right now. That's a real portfolio!

Slide 6 — Dark mode

CSS nesting with body.dark .card is a powerful pattern. Explain that adding one class to body can change the entire page's colour scheme — that's why dark mode is only a few lines of JS.

Slide 8 — Wrap up

End the lesson by pushing the portfolio to GitHub Pages — it's free and the site goes live at username.github.io/portfolio. Show her how in 5 minutes. Seeing your work live on the internet is incredibly motivating.
