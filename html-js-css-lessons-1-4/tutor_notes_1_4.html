Tutor Notes

Lesson 1 — HTML & CSS Basics

Student builds their first About Me webpage from scratch using HTML tags and CSS styling.

Duration: ~30 min Level: Absolute beginner File: aboutme.html Tools: VS Code + Chrome

Learning objectives

  • Understand what HTML is and how the browser reads it
  • Know the basic HTML skeleton (DOCTYPE, html, head, body)
  • Use at least 5 HTML tags correctly (h1, p, a, ul/li, div)
  • Write a CSS rule with selector, property and value
  • Use a CSS class to style multiple elements
  • Distinguish between padding, margin and border

Teaching notes — slide by slide

Slide 3 — What is HTML?

Ask her to open VS Code and create a new file called aboutme.html before you explain tags. Seeing the blank file makes the explanation click faster.

Good analogy: HTML is like a recipe — the browser follows the tags to know what to cook (display).

Slide 4 — Essential HTML tags

Common mistake: forgetting the closing tag (e.g. writing <h1> but no </h1>). Tell her VS Code will highlight unmatched tags in red — a useful self-check.

Let her type each tag herself, one by one. Resist the urge to show a completed example too early.

Slide 5 — Page skeleton

Explain: <head> is behind the scenes (settings), <body> is what the user sees. Use the analogy of an iceberg — head is below the water, body is the visible part.

Slide 6 — CSS basics

Live demo trick: open Chrome DevTools (F12 → Elements → Styles) and change a CSS value live. She can see the page update instantly — very "wow" moment for beginners.

Slide 7 — Common CSS properties

Focus on: color, background-color, font-size, margin, padding. Don't introduce too many at once.

Students often confuse margin and padding. Use this: padding = the pillow inside the box, margin = the space around the box on the table.

Common errors to watch for

ErrorLikely causeHow to fix
Page shows raw codeFile saved as .txt not .htmlFile → Save As → change extension to .html
CSS not workingTypo in property name or missing semicolonCheck the DevTools console for red errors
Closing tag missingForgot </div> or </p>VS Code highlights unmatched tags — look for red squiggles
Colour not changingWrong CSS selector (used #id instead of .class)Open DevTools and inspect the element — check which rule is applied
Image not showingWrong file pathMake sure the image is in the same folder as the HTML file

Challenge hints (if she gets stuck)

Change background colour

body { background-color: pink; }

Add a border to card

.card { border: 2px solid blue; }

Wrap-up questions to ask her

  • "What's the difference between <head> and <body>?"
  • "Can you explain what padding does in your own words?"
  • "How would you add a second card to the page?"
  • "What happens if you remove the .card class from a div?"

Lesson 2 — JavaScript Basics

Student adds interactivity to their About Me page using JS variables, functions, DOM, and if/else.

Duration: ~30 min Level: Beginner JS File: aboutme.html (continued) Prerequisite: Lesson 1 done

Learning objectives

  • Declare variables using let and const
  • Know the 3 main data types: String, Number, Boolean
  • Write and call a function
  • Use document.getElementById() to find an HTML element
  • Use innerHTML to change page content
  • Write a basic if/else statement

Teaching notes — slide by slide

Slide 3 — Variables

Start by opening Chrome DevTools (F12 → Console tab) and typing let name = "Sarah" then console.log(name). The console is a great sandbox — no file saving needed to experiment.
Students often use var from older tutorials online. Gently redirect to let and const and explain why they're better.

Slide 4 — Functions

Analogy: a function is like a vending machine — you press a button (call the function), it does something, and gives you back a result.

Have her write the function first with just a console.log inside, then call it. Don't go straight to DOM manipulation — build confidence step by step.

Slide 5 — Connecting JS to HTML

Remind her: the <script> tag must go at the BOTTOM of <body>, not in <head>. If it's in <head>, the DOM isn't loaded yet and getElementById will return null.

Slide 6 — DOM

Good demo: open any website, right-click → Inspect → click an element. Then in the console type document.getElementById("something").innerHTML = "I changed this!". Very impressive moment!

Slide 7 — if/else

Remind her about parseInt() — input fields always return strings. 17 > 18 works but "17" > "18" compares alphabetically, which can give wrong results.

Common errors to watch for

ErrorLikely causeHow to fix
getElementById returns null<script> is in <head> — DOM not ready yetMove <script> to bottom of <body>
Function not definedTypo in function name, or onclick name doesn't matchCheck spelling exactly — JS is case sensitive
if/else giving wrong resultUsed = instead of === for comparison= assigns, === compares. Always use === in conditions
NaN errorsForgot parseInt() when doing maths with input valuesWrap input.value in parseInt() or parseFloat()
Nothing happens on clickonclick attribute missing or misspelledCheck the HTML button tag has onclick="functionName()"

Key concepts to reinforce

The DOM update pattern

// 1. Find the element
let el = document.getElementById("myId");
// 2. Change it
el.innerHTML = "New text";
el.style.color = "red";

if/else template

if (condition) {
  // runs if TRUE
} else {
  // runs if FALSE
}

Wrap-up questions to ask her

  • "What's the difference between let and const?"
  • "Why do we use parseInt() when reading from an input?"
  • "What does innerHTML do?"
  • "Can you add a button that changes the heading colour to green?"

Lesson 3 — CSS Layouts & Flexbox

Student learns the box model, CSS classes, and Flexbox to build a navbar, cards, and real page layouts.

Duration: ~30 min Level: Intermediate CSS File: layouts.html (new file) Prerequisite: Lessons 1 & 2 done

Learning objectives

  • Write and apply a CSS class vs ID correctly
  • Turn on Flexbox with display: flex
  • Use justify-content and align-items to position elements
  • Build a working navbar using Flexbox
  • Arrange cards in a row with gap and flex-wrap

Teaching notes — slide by slide

Slide 3 — Box model

Open any webpage, right-click any element → Inspect. In DevTools, hover over an element — Chrome draws the box model visually (blue = content, green = padding, orange = margin). This is much more memorable than a diagram.
Key insight: box-sizing: border-box makes width include padding and border — always use it at the top of every CSS file with * { box-sizing: border-box; }.

Slide 4 — CSS classes vs IDs

Rule of thumb: use classes for styling (reusable), use IDs for JavaScript targeting (unique). Avoid styling with IDs as it causes specificity headaches.

Common confusion: forgetting the dot (.) before class names in CSS. In HTML it's class="card", in CSS it's .card { }.

Slide 5 — Flexbox

The best Flexbox teaching tool is Flexbox Froggy (flexboxfroggy.com) — mention it as homework. Very fun and free.

Live demo: add display: flex to a container in DevTools and watch the children rearrange instantly.

Remember: Flexbox affects the CHILDREN of the container, not the container itself. Students sometimes add display:flex to the wrong element.

Slide 6 — Navbar

Build this together live. Start with just two divs inside the navbar, then add Flexbox step by step. Let her see each property change the layout before adding the next.

Slide 7 — Profile card

The border-radius: 50% trick for circles is always a crowd-pleaser. Let her change the avatar colour and initials to personalise it.

Common errors to watch for

ErrorLikely causeHow to fix
Flexbox not workingdisplay:flex added to child, not containerAdd display:flex to the PARENT element
Cards stacking verticallyflex-direction defaults to column if set wrongAdd flex-direction: row (or remove it — row is the default)
Card overflows containerNo flex-wrap setAdd flex-wrap: wrap to the container
Width not matching expectationMissing box-sizing: border-boxAdd * { box-sizing: border-box; } at top of CSS
Gap not workingOld browser — gap in flexbox needs Chrome 84+Use margin-right on children as fallback

Wrap-up questions to ask her

  • "What property turns on Flexbox?"
  • "What's the difference between justify-content and align-items?"
  • "How do you make an image circular with CSS?"
  • "What does flex-wrap: wrap do?"

Lesson 4 — JS Arrays, Loops & Events

Student builds a complete To-Do List app using arrays, loops, event listeners, and the DOM.

Duration: ~30 min Level: Intermediate JS File: todo.html (new file) Prerequisite: Lessons 1–3 done

Learning objectives

  • Create an array and access items by index
  • Add items to an array with push() and remove with splice()
  • Loop through an array using forEach
  • Use addEventListener instead of inline onclick
  • Build and render HTML dynamically from an array
  • Understand why arrays start at index 0

Teaching notes — slide by slide

Slide 3 — Arrays

Start in the DevTools console: type let fruits = ["Apple", "Mango", "Durian"] and then fruits[0]. Let her guess what fruits[2] returns before you run it.
The index-0 concept trips up EVERY beginner. Take time here. Ask her: "If there are 3 items, what is the last index?" (Answer: 2, not 3). Reinforce this with fruits.length - 1.

Slide 4 — Loops

Teach forEach first — it reads naturally in English. Only introduce the classic for loop if she wants to know how it works under the hood.

Analogy for forEach: "For each item in my shopping list, print it out." Reading code like a sentence helps beginners understand the pattern.

Slide 5 — Event listeners

Explain why addEventListener is better than onclick in HTML: it keeps your JS and HTML separate (separation of concerns). This is how professional code is written.

Live demo: add a click listener in DevTools console: document.querySelector("h1").addEventListener("click", function() { alert("clicked!") }). Very impressive.

Slides 6 & 7 — To-do app

Build this step by step — don't show the finished code. Start with: (1) array + console.log, (2) render list to page, (3) add input + button, (4) delete. Each step should work before moving to the next.
The render() function pattern (clear and redraw everything) is a fundamental concept in web development. Highlight it: "This is how React works too — state changes, then re-render."

Common errors to watch for

ErrorLikely causeHow to fix
Array item undefinedAccessed index out of bounds (e.g. fruits[5] in a 3-item array)Check array.length before accessing
forEach not workingTypo — it's forEach not foreach (case sensitive)JS is case sensitive — check exact spelling
Event fires immediatelyWritten onclick="addTask()" vs addEventListener("click", addTask)With addEventListener, don't include () after the function name
Items duplicatingForgot to clear innerHTML before re-renderingAdd ul.innerHTML = "" at the top of render()
Delete deletes wrong itemIndex is wrong after array mutatesUse filter() by id — safer than splice() by index

Key patterns to reinforce

Add to array + re-render

tasks.push(newTask);
render(); // always re-render after change

Remove from array

tasks = tasks.filter(function(t) {
  return t.id !== idToDelete;
});
render();

Build HTML from array

let html = "";
tasks.forEach(function(t) {
  html += "<li>" + t.text + "</li>";
});
list.innerHTML = html;

Enter key event

input.addEventListener("keydown", function(e) {
  if (e.key === "Enter") addTask();
});

Wrap-up questions to ask her

  • "What index does an array start at, and why?"
  • "What does push() do? What does filter() do?"
  • "Why do we call render() after every change?"
  • "What's the difference between addEventListener and onclick?"
  • "How would you add a 'priority' field to each task object?"
